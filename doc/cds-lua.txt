                                                                       *cds-lua*
cds-lua is a common library for Neovim plugins written in a functional
style: `task` for asynchronous work, and the modules that grew out of the
plugins that use them (processes, HTTP, OAuth, redraws). The
vocabulary they are written in, |cds.fp| for lists and |cds.result| for
the Result convention, is the cds-lua-fp rock (|cds-lua-fp|), which this
library depends on; |cds.needs|, from the same rock, is how a plugin takes
both: it declares the functions it calls, and the check at startup names
what the libraries installed lack. Each module is pure Lua that names no
plugin; every function answers `value` or `nil, err`, and `nil` alone
means failure.

This manual covers the modules the plugins call in common. The rest
(OAuth, secrets, processes, dates, images) are documented in their source,
which the language server shows on hover, and on the reference site.

  Tasks ........................................................... |cds.task|
  vim.async, named once .......................................... |cds.async|
  HTTP through curl ............................................... |cds.http|
  A buffer drawn again in place ................................. |cds.redraw|
  What a plugin is waiting on ................................. |cds.activity|

                                                                      *cds.task*
A Task is a lazy asynchronous result over vim.async: a recipe, so nothing
runs until |cds.Task:run()|, and a pipeline can be built, combined and
handed around as a value. Composition passes one value and one error, in
the Result convention; nil and false are valid successes. >lua

  local Task = require("cds.task")
  Task.new(function()
    return http.request({ method = "GET", url = url })
  end)
    :bind_result(parse)
    :map_err(function(err) return "the index: " .. err.message end)
    :run()
<

                                                                     *cds.async*
The one module that names vim.async. It is new in Neovim 0.13 and may
still change before that release; every caller goes through here, so a
rename is a one-file fix. The module is vim.async itself, under a type
declared here as the four functions the family calls, each a step in the
Result convention: a value, or nil and its error. vim.async's own
annotations are variadic generics the language server cannot follow.

------------------------------------------------------------------------------
Alias ~
{cds.async.Step} `(fun(...: any): any, any)` a value, or nil and its error

------------------------------------------------------------------------------
Class ~
{cds.async}
Fields ~
{run} `(fun(fn: cds.async.Step, ...: any): vim.async.Task)` starts the step as a task
{await} `(fun(...: any): any, any)` a task, or (argc, callback-taking fn, args...)
{timeout} `(fun(ms: integer, task: vim.async.Task): any, any)` the task's answer, or an error at the deadline
{semaphore} `(fun(permits: integer): vim.async.Semaphore)`

                                                                      *cds.http*
Every option travels as a config file on curl's stdin (`--config -`),
so a bearer token or client secret never appears in argv or in `ps`.
Transfers are compressed when the server offers it, and the body comes
back decoded. An HTTP response of any status returns normally; only a
transport failure returns nil plus a classified error.

                                                                    *cds.redraw*
Redraws a buffer while it is on screen and keeps the reader's place. The
draw runs once, and every window showing the buffer is put back where it
was, so the layout stays the reader's. The place is a key the caller
names (a line, a section's tag, an item's signature), taken before the
draw and sought after it; with no key, or when the key is gone, the
window keeps its line, clamped to the new length. `places` and `restore`
are the two halves, for a draw whose text lands later (a listing filled
page by page); `windows` wraps both around a draw that returns with its
text. Dependents of the buffer's text (a sidebar, folds) are the caller's
to refresh, with the windows answered.

------------------------------------------------------------------------------
Class ~
{cds.redraw.Keep}
Fields ~
{key} `(fun(win: integer): any)` the window's place before the draw; nil for none
{seek} `(fun(win: integer, key: any): boolean)` the window onto its place after; false when the place is gone

------------------------------------------------------------------------------
Class ~
{cds.redraw.Places}
Fields ~
{buf} `(integer)`
{wins} `(integer[])` the windows showing the buffer when taken
{of} `(table<integer, { cursor: integer[], key: any }>)` each window's cursor and place

------------------------------------------------------------------------------

                       `redraw.restore`({places}, {keep})
Puts each window back on its place after the draw: where `keep` finds the

------------------------------------------------------------------------------
                                                          *cds.redraw.windows()*
                    `redraw.windows`({buf}, {draw}, {keep})
Runs `draw` with the windows showing `buf`, then puts each window back:
on the place `keep` names when it is still there, on its line otherwise.
The two halves as one call, for a draw whose text is there when it
returns. Answers the windows, for the caller's own dependents.

`(integer[])` wins

                                                                  *cds.activity*
Tracks every long call a plugin has out, for a statusline segment. A run
is tracked from its start to its end; the segment names the runs out with
how long each has been out, a User autocmd fires on both edges, and a
timer redraws the statusline once a second while anything is out, so the
seconds move without the statusline plugin polling. The autocmd name and
the clock are parameters, so the module carries nothing of any one plugin.

                                                          *cds.Activity:track()*
                   `Activity:track`({kind}, {label}, {task})
Tracks `task` from now to its completion, however it ends. The end is
observed, never awaited: on this nightly a failing child fails the task
awaiting it, and the tracker must not die with what it tracks. The finish is
scheduled, since the completion callback may run in a fast event, where
firing an autocmd is refused.
Parameters ~

{label} `(string)`
{task} `(vim.async.Task)` what cds.Task:run answers
Return ~
`(vim.async.Task)` task

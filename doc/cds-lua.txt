                                                                       *cds-lua*
A common library for Neovim plugins written in a functional style:
`fp` and `result` for the vocabulary, `task` for asynchronous work, and the
modules that grew out of the plugins that use them (processes, HTTP,
documents, redraws). Each module is pure Lua that names no plugin; every
function answers `value` or `nil, err`, and `nil` alone means failure
(|cds.result|).

The library grows by addition: a function keeps its contract under its
name, and a different contract gets a different name, so a plugin can
declare the functions it uses and run on any commit that has them
(|cds.needs|). A name a module does not have fails at the call, in words
(|cds.module|).

This manual covers the modules the plugins call in common. The rest (the
document readers, OAuth, processes, dates) are documented in their source,
which the language server shows on hover, and on the reference site.

  Taking the library ............................................. |cds.needs|
  Names a module does not have .................................. |cds.module|
  The Result convention ......................................... |cds.result|
  Lists ............................................................. |cds.fp|
  Tasks ........................................................... |cds.task|
  vim.async, named once .......................................... |cds.async|
  HTTP through curl ............................................... |cds.http|
  A buffer drawn again in place ................................. |cds.redraw|
  What a plugin is waiting on ................................. |cds.activity|

                                                                     *cds.needs*
A plugin takes the library as a lazy.nvim dependency, declared in the
`lazy.lua` at its root: >lua

  return {
    "cds-io/<plugin>",
    dependencies = { { "cds-io/cds-lua", lazy = true } },
  }
<
The dependency tracks `main` with no pin, so one `:Lazy update` moves the
family together, and one copy of `lua/cds/` is on the runtimepath, so
`require("cds.fp")` has one file to resolve to.

What the plugin calls is declared in `lua/<plugin>/needs.lua`, by module
and name: a function, or a table such as `http.status`. >lua

  ---@type cds.needs.Capabilities
  return {
    fp = { "map", "filter" },
    http = { "request", "status" },
  }
<
The plugin's entry runs |cds.needs.check()| first and refuses the whole
plugin, in one message naming the remedy, when the library installed lacks
a name. Its spec harness wraps the declared modules through
|cds.needs.strict()|, so a call the declaration leaves out fails the spec
in words, and the declaration stays what the code uses.

The one check a plugin keeps for itself is whether this module loads: a
library too old to carry it fails that `require`, which is the answer.

------------------------------------------------------------------------------
Alias ~
{cds.needs.Capabilities} `(table<string, string[]>)` cds module to the functions used

------------------------------------------------------------------------------
                                                           *cds.needs.missing()*
                        `needs.missing`({capabilities})
Lists the capabilities the library present lacks, as "fp.filter" names,
modules in name order and each in declaration order: a name the module has
nothing under, or every name of a module that does not load.
Parameters ~
{capabilities} `(cds.needs.Capabilities)`
Return ~
`(string[])`

------------------------------------------------------------------------------
                                                             *cds.needs.check()*
                    `needs.check`({plugin}, {capabilities})
Answers nil when everything declared is here; otherwise one sentence for the
reader, naming the plugin, the missing functions and the remedy.
Parameters ~
{plugin} `(string)` truth-table.nvim
{capabilities} `(cds.needs.Capabilities)`
Return ~
`(string|nil)`

------------------------------------------------------------------------------
                                                            *cds.needs.strict()*
                    `needs.strict`({plugin}, {capabilities})
Replaces each declared module, in package.loaded, with a proxy that holds
nothing itself: a declared name reads from the real module, so a seam a spec
replaces there (`proc.runner`) is what the plugin's own code reads; any
other name raises, naming the plugin whose declaration is short; a write
goes to the real module, since a plugin setting a hook the module leaves nil
(`http.trace`) is not declaring a name it reads. The library's own modules
pass through, since they use each other beyond the declaration; a module the
tier cannot load (one that needs `vim`, under plain busted) is left alone.
For a spec harness, before any spec runs.
Parameters ~
{plugin} `(string)`
{capabilities} `(cds.needs.Capabilities)`


==============================================================================
                                                                    *cds.module*
Every module of the library returns through |cds.module.wrap()|, so a
name a module does not have fails at the call with the module's name and
the key in words, where plain Lua says "attempt to call field 'filter_mop'
(a nil value)" somewhere later. The usual cause is a cds-lua older than the
code calling it, and the message says so.

A lookup on a module therefore answers a function for every name. A test
for a name's presence asks |cds.module.is_fallback()| of what the lookup
answered, as cds.needs does; `rawget` would miss a module whose names come
through a metatable of its own, as vim.async's do.

A module ends with >lua

  return require("cds.module").wrap("fp", M)
<
and declares `---@class cds.fp` above its table, so the language server
carries the module's type to every caller and a misspelt name is an
undefined field at edit time. The named function is the form: a `__call`
metamethod in its place loses the type.

`(T)`

------------------------------------------------------------------------------

==============================================================================
                                                                    *cds.result*
Lua's value, error convention as a small pipeline. A function answers
`value`, or `nil, err`; only nil fails, so false and zero are valid
successful values. A step that can refuse goes through `bind` or
`traverse`; one that cannot goes through `map`, so a reader can tell the
two apart at the call. Where a step cannot fail and there is no error to
carry, |cds.fp.map()| is the plain list map. Errors are values until the
dispatch rim turns the last one into a message for the reader.

------------------------------------------------------------------------------
                                                             *cds.result.bind()*
                      `result.bind`({value}, {err}, {fn})
Passes the value through `fn`, which may refuse (nil, err), and an error
through untouched.
Parameters ~
{value} `(T?)`
{err} `(any)`
{fn} `(fun(value: T): U?, any)`
Return ~
`(U?)` value
`(any)` err

------------------------------------------------------------------------------
                                                                *cds.result.map*
                                  `result.map`
Passes the value through `fn`, which always answers, and an error through
untouched. The same step as bind: the name says at the call whether `fn` can
refuse.

------------------------------------------------------------------------------
                                                          *cds.result.context()*
                   `result.context`({value}, {err}, {prefix})
Passes the value through untouched and puts `prefix` in front of an error,
so a failure deep in a pipeline says where it was met ('Parse error in "A
and": ...').
Parameters ~
{value} `(T?)`
{err} `(string?)`
{prefix} `(string)`
Return ~
`(T?)` value
`(string?)` err

------------------------------------------------------------------------------
                                                         *cds.result.traverse()*
                       `result.traverse`({values}, {fn})
Runs fn(value, index) over every item, stopping at the first refusal, and
answers the list of answers, or nil and that error.
Parameters ~
{values} `(T[])`
{fn} `(fun(value: T, index: integer): U?, any)`
Return ~
`(U[]?)` values
`(any)` err

                                                                        *cds.fp*
map, filter, reduce, find, find_map, any, all, set and unique over
lists: the house list vocabulary, for the pure modules in the first place,
which run under plain Lua 5.1 (none of these built in) and without `vim`,
so without vim.iter. A list is a sequence (items at 1..n, no holes), read
with ipairs. Map, filter and unique return fresh lists, set a fresh table,
reduce the final accumulator, find the item, any and all a boolean. The
helpers do not modify the input list. The function argument comes last, so
one written out over several lines reads as a block.

there.

`(U[])`

                                                                      *cds.task*
A lazy asynchronous result over vim.async. A Task is a recipe: nothing
runs until |cds.Task:run()|, so a pipeline is built, combined and handed
around as a value. Composition passes one value and one error, in the
Result convention; nil and false are valid successes. >lua

  local Task = require("cds.task")
  Task.new(function()
    return http.request({ method = "GET", url = url })
  end)
    :bind_result(parse)
    :map_err(function(err) return "the index: " .. err.message end)
    :run()
<

Makes a Task of fn, which may yield and returns (value, err). Exceptions
become errors at run.

                                                                     *cds.async*
The one module that names vim.async. It is new in Neovim 0.13 and may
still change before that release; every caller goes through here, so a
rename is a one-file fix. The module is vim.async itself, under a type
declared here as the four functions the family calls, each a step in the
Result convention: a value, or nil and its error. vim.async's own
annotations are variadic generics the language server cannot follow.

------------------------------------------------------------------------------
Alias ~
{cds.async.Step} `(fun(...: any): any, any)` a value, or nil and its error

------------------------------------------------------------------------------
Class ~
{cds.async}
Fields ~
{run} `(fun(fn: cds.async.Step, ...: any): vim.async.Task)` starts the step as a task
{await} `(fun(...: any): any, any)` a task, or (argc, callback-taking fn, args...)
{timeout} `(fun(ms: integer, task: vim.async.Task): any, any)` the task's answer, or an error at the deadline
{semaphore} `(fun(permits: integer): vim.async.Semaphore)`

                                                                    *cds.redraw*
A buffer drawn again while it is on screen: the draw runs once, and
every window showing the buffer is put back on its place, so the layout
stays the reader's. The place is a key the caller names (a line, a
section's tag, an item's signature) taken before the draw and sought after
it; with no key, or when the key is gone, the window keeps its line,
clamped to the new length. The two halves are `places` and `restore`, for
a draw whose text lands later (a listing filled page by page); `windows` is
both around a draw that returns with its text. Dependents of the buffer's
text (a sidebar, folds) are the caller's to refresh, with the windows
answered.

------------------------------------------------------------------------------
Class ~
{cds.redraw.Keep}
Fields ~
{key} `(fun(win: integer): any)` the window's place before the draw; nil for none
{seek} `(fun(win: integer, key: any): boolean)` the window onto its place after; false when the place is gone

------------------------------------------------------------------------------
Class ~
{cds.redraw.Places}
Fields ~
{buf} `(integer)`
{wins} `(integer[])` the windows showing the buffer when taken
{of} `(table<integer, { cursor: integer[], key: any }>)` each window's cursor and place

------------------------------------------------------------------------------

Takes the windows showing `buf` and each one's place before a draw: its

Parameters ~

Return ~
`(cds.redraw.Places)`

------------------------------------------------------------------------------

Puts each window back on its place after the draw: where `keep` finds the

Runs `draw` with the windows showing `buf`, then puts each window back:

                                                                  *cds.activity*
Every long call out, for a statusline segment. A run is tracked from
its start to its end; the segment names the runs out with how long each
has been out, a User autocmd fires on both edges, and a timer redraws the
statusline once a second while anything is out, so the seconds move
without the statusline plugin polling. The autocmd name and the clock are
parameters, so the module carries nothing of any one plugin.

------------------------------------------------------------------------------
                                                          *cds.Activity:track()*
                   `Activity:track`({kind}, {label}, {task})
Tracks `task` from now to its completion, however it ends. The end is
observed, never awaited: on this nightly a failing child fails the task
awaiting it, and the tracker must not die with what it tracks. The finish is
scheduled, since the completion callback may run in a fast event, where
firing an autocmd is refused.
Parameters ~
{kind} `(string)`
{label} `(string)`
{task} `(vim.async.Task)` what cds.Task:run answers
Return ~
`(vim.async.Task)` task
